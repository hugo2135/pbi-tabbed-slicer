# 分頁籤階層篩選器 (Tabbed Hierarchy Slicer)

Power BI 自訂視覺。把多個原本各自獨立的篩選器整合進一個視覺：上方是分頁籤，下方是可搜尋、可展開的多層勾選清單。

- 分頁籤，寬度不夠時自動減少並出現 `‹ ›` 分頁鈕（滾輪也能橫捲）
- 每個頁籤是一組獨立的勾選清單，層數不限
- 全文搜尋，命中子孫時自動展開分支
- 三態勾選（全選 / 半選 / 未選），父子連動
- 頁籤之間會互相篩選，等同多個原生篩選器並存
- 各頁籤可自訂背景色
- 完全響應式，隨視覺外框縮放

---

## 安裝

本 repo 不附建置好的 `.pbiviz`，需自行打包：

```bash
npm install
npm run package    # 產出 dist/*.pbiviz
```

Power BI Desktop → 視覺效果窗格 `…` → **從檔案匯入視覺效果** → 選 `dist/*.pbiviz`。

> 更新版本時：先在視覺效果窗格**移除舊的**，再重新匯入。直接覆蓋匯入有時不會生效。

---

## 快速開始

1. 把視覺放到報表上
2. 右側「欄位」窗格 → `頁籤 1 欄位` 拖入一個維度欄位（例如 `品牌`）
3. `頁籤 2 欄位` 拖入另一個（例如 `品類`）
4. **`篩選依據量值` 拖入任一量值** —— 不放的話清單不會隨其他篩選縮減，見下方說明
5. 格式窗格 → 頁籤 → 自訂各頁籤名稱

---

## 欄位窗格

**`頁籤 1 欄位` ~ `頁籤 20 欄位`**：一個區塊 = 一個頁籤，沒放欄位不顯示。同一區塊放多個欄位 = 該頁籤的階層（第 1 個欄位最上層，層數不限）。頁籤名稱預設取第一個欄位名稱，可在格式窗格覆寫。

**`篩選依據量值`（選填，強烈建議放）**：視覺靠 `SUMMARIZECOLUMNS` 取資料，沒放量值時查詢不套用其他視覺的篩選（`SUMMARIZECOLUMNS(品牌, 品類)` 回傳所有值）；放了量值才會套用篩選、只回傳實際有資料的組合。放什麼量值不重要，重點是要有一個量值把篩選帶進查詢。

## 格式窗格

| 卡片 | 設定 |
|---|---|
| **頁籤** | 每頁顯示頁籤數上限、是否自動用欄位名稱當頁籤名、啟用頁籤色彩、各頁籤的自訂名稱與背景色 |
| **篩選行為** | 篩選模式、頁籤之間互相篩選、單選、勾選父項連動子項、顯示全選列、預設全部展開、切換頁籤清除搜尋 |
| **標題** | 顯示、標題文字、已選取數量、字型色彩與大小 |
| **搜尋** | 顯示搜尋框、提示文字、是否搜尋所有層級 |
| **項目** | 字型/強調/背景色彩、字級、列高、階層縮排、子項數量 |

小技巧：標題右側的「已選 N 項」點一下就會清除所有勾選。

**篩選模式**：「篩選器 (Filter)」送出真正的篩選條件，等同原生交叉篩選器，會影響所有視覺並自動還原狀態；「選取 (Select)」用 `SelectionManager` 做交叉醒目提示，其他視覺是高亮而非過濾。

**頁籤色彩**：預設關閉，開啟後才會出現各頁籤背景色選擇器。目前頁籤用完整顏色，其他自動淡化 45%；文字色依背景亮度自動切換深色/白色；預設配色依頁籤總數自動分配色相，想調整整體色調可改 `src/settings.ts` 最上方三個常數。

**頁籤之間互相篩選**（預設開啟，僅「篩選器」模式作用）：勾了頁籤 1 的項目後，其他頁籤清單只剩相關聯的選項，如同多個原生篩選器並存。切換頁籤會重新查詢一次（畫面會閃一下），介意的話可以關掉。

---

## ⚠️ 三個限制（Power BI 本身的規則）

1. **所有頁籤的欄位必須來自「有關聯」的資料表**，否則會出現 `InvalidUnconstrainedJoin`。因為一個視覺只執行一次查詢，所有頁籤欄位進同一個 DataShape，無關聯的表無法產生結果。無解，只能在模型裡建立關聯。
2. **各頁籤欄位會交叉組合，總列數上限 30,000**。適合低基數維度（品牌、品類、地區…），不適合高基數欄位（訂單編號、客戶 ID、日期時間）。超過上限時清單會缺項，右上角出現警告圖示。
3. **各頁籤共用同一次查詢，無法個別控制**——「篩選依據量值」是整個視覺共用的，不能針對單一頁籤設定。

---

## 調整頁籤欄位區塊的數量

`capabilities.json` 的資料區塊必須靜態宣告（格式窗格無法動態調整），目前預先開好 20 個。要增減數量：

```bash
node tools/set-tabs.js 12    # 改成 12 個頁籤欄位區塊
npm run package               # 重新打包
```

腳本會同步更新 `src/dataModel.ts` 的 `MAX_TABS` 與 `capabilities.json` 的四處相關設定，並把結果寫到 `tools/set-tabs.log`（**沒看到五項全部 `[OK]` 就是沒改成功**）。跑完務必接著 `npm run package` 並在 Power BI Desktop 重新匯入。

## 開發

### ⚠️ 專案路徑必須是純英文

`pbiviz package` 在含中文（或任何非 ASCII 字元）的路徑下會讓 node.exe 直接 segfault（無 stdout/stderr、事件檢視器也查不到），只留下寫到一半的 `.tmp/precompile/visualPlugin.ts`。`npm install` 在同樣路徑下正常，容易誤判成其他問題。務必把專案放在純英文路徑下。

### 指令

```bash
npm install        # 第一次必跑
npm start          # pbiviz start，開發者視覺即時預覽
npm run package    # 產出 dist/*.pbiviz
npm run typecheck
```

打包卡住時先刪掉殘留的 `.tmp/` 再試。

### 檔案

| 檔案 | 內容 |
|---|---|
| `src/visual.ts` | 主體：DOM 建構、版面計算、頁籤/搜尋/勾選樹渲染、三態勾選、色彩工具 |
| `src/dataModel.ts` | categorical dataView 依資料角色分群 → 各頁籤的階層樹 |
| `src/filterEngine.ts` | Basic/Tuple Filter 組裝、自我篩選、SelectionManager、篩選狀態還原 |
| `src/settings.ts` | 格式窗格設定模型、預設頁籤配色產生器 |
| `style/visual.less` | 樣式，色彩以 CSS 變數由格式窗格注入 |
| `tools/set-tabs.js` | 一鍵調整頁籤欄位區塊數量 |
| `capabilities.json` | 20 組頁籤資料角色 + 選填量值 + 單一 dataViewMapping + 格式物件 |

## 疑難排解

| 症狀 | 原因 / 解法 |
|---|---|
| `npm run package` 沒輸出就結束／`Segmentation fault` | 專案路徑含非 ASCII 字元，搬到純英文路徑 |
| `Command failed: npm list powerbi-visuals-api` | 沒跑過 `npm install`，或用到全域的舊版 pbiviz |
| `InvalidUnconstrainedJoin` | 頁籤裡混了無關聯的資料表 |
| 清單不隨其他視覺的篩選縮減 | 沒放「篩選依據量值」 |
| 切到別的頁籤，清單沒被本視覺的勾選縮減 | 開啟「頁籤之間互相篩選」，且篩選模式要是「篩選器 (Filter)」 |
| 切換頁籤時畫面閃一下／有延遲 | 「頁籤之間互相篩選」開啟時每次切頁籤都會重新查詢，不需要可關掉 |
| 右上角出現警告圖示 | 資料達 30,000 列上限，把高基數欄位移出去 |
| 拖了欄位卻沒出現頁籤 | 該欄位所有值都是空的；或 `capabilities.json` 漏了該角色（用 set-tabs 重建） |
| 勾選後其他視覺沒反應 | 篩選模式被設成「選取 (Select)」；或報表設定為不允許互動 |
| 改了格式設定沒反應 | 屬性可能沒在 `capabilities.json` 宣告，或名稱與 `settings.ts` 不一致 |
| 看不到各頁籤的背景色設定 | 格式窗格 → 頁籤 → 先打開「啟用頁籤色彩」 |
| 重新匯入視覺後沒變化 | 先在視覺效果窗格移除舊的，再匯入 |

## 已知限制

- 選取模式下，多層頁籤的交叉醒目提示以「勾選節點所在層級」的識別為準。
- 「勾選父項時連動子項」關閉時，父層仍會依子層狀態顯示半選，但只有實際勾到的節點會送進篩選。
- 頁籤數量上限 50（`tools/set-tabs.js` 的防呆），實務上受視覺寬度限制，超過 20 個已不易操作。
