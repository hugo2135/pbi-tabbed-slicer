# 分頁籤階層篩選器 (Tabbed Hierarchy Slicer)

Power BI 自訂視覺。把多個原本各自獨立的篩選器整合進一個視覺：上方是分頁籤，下方是可搜尋、可展開的多層勾選清單。互動方式取自參考檔 `條目瀏覽小視窗.html`。

- 分頁籤，寬度不夠時自動減少並出現 `‹ ›` 分頁鈕（滾輪也能橫捲）
- 每個頁籤是一組獨立的勾選清單，層數不限
- 全文搜尋，命中子孫時自動展開分支
- 三態勾選（全選 / 半選 / 未選），父子連動
- 有下層的項目可用**右鍵**快速展開／折疊，另有「全部展開／全部折疊」工具列
- **Shift 區間勾選**、搜尋後可一鍵全選符合的項目
- 內建「?」操作說明面板，可外掛完整文件網址
- 頁籤之間會互相篩選，等同多個原生篩選器並存
- 各頁籤可自訂背景色
- 完全響應式，隨視覺外框縮放

## 快速開始

1. 把視覺放到報表上
2. 右側「欄位」窗格 → `頁籤 1 欄位` 拖入一個維度欄位（例如 `品牌`）
3. `頁籤 2 欄位` 拖入另一個（例如 `品類`）
4. **`篩選依據量值` 拖入任一量值** —— 不放的話清單不會隨其他篩選縮減，見下方說明
5. 格式窗格 → 頁籤 → 自訂各頁籤名稱

## 欄位窗格

### 頁籤 1 欄位 ~ 頁籤 20 欄位

- **一個區塊 = 一個頁籤**。沒放欄位的區塊不會顯示成頁籤。
- **同一個區塊放多個欄位 = 該頁籤的階層**，第 1 個欄位是最上層，層數不限。

  例：`頁籤 1 欄位` 依序放「區域 → 縣市 → 門市」，得到三層可展開的勾選樹。
- 頁籤名稱預設取該頁籤第一個欄位的名稱，可在格式窗格覆寫。

### 篩選依據量值 (選填)

**這個欄位在修查詢，不是修畫面。強烈建議放一個量值進去**，例如 `COUNTROWS(all_order_items)` 或任何既有的計數量值。

視覺的資料是靠 DAX 的 `SUMMARIZECOLUMNS` 取回的：

| | 查詢長相 | 結果 |
|---|---|---|
| **沒放量值** | `SUMMARIZECOLUMNS(品牌, 品類)` | 回傳這些欄位的**所有值**，不套用篩選內容。其他視覺怎麼篩，清單都不會變 |
| **放了量值** | `SUMMARIZECOLUMNS(品牌, 品類, "m", [訂單數])` | 套用篩選內容，只回傳實際有資料的組合。清單會跟著其他視覺的篩選縮減 |

放什麼量值不重要（視覺不顯示它的值），重點是「有一個量值把篩選內容帶進查詢」。選一個跟這些維度有關聯的事實表計數即可。

它管的是「本視覺會不會被**其他視覺**的篩選縮減」。頁籤之間互相篩選是另一套機制，見下方專章。

## 格式窗格

| 卡片 | 設定 |
|---|---|
| **頁籤** | 每頁顯示頁籤數上限、是否自動用欄位名稱當頁籤名、啟用頁籤色彩、各頁籤的自訂名稱與背景色 |
| **篩選行為** | 篩選模式、頁籤之間互相篩選、單選、勾選父項連動子項、顯示全選列、預設全部展開、切換頁籤清除搜尋 |
| **標題** | 顯示、標題文字、已選取數量、**說明按鈕**、**說明文件網址**、字型色彩與大小 |
| **搜尋** | 顯示搜尋框、提示文字、是否搜尋所有層級、**伺服器端搜尋**、**比對層級** |
| **項目** | 字型/強調/背景色彩、字級、列高、階層縮排、子項數量 |

小技巧：

- 搜尋列下方是一條**固定的狀態列**（不隨清單捲動）：左邊「全選」、右邊「未篩選／已選 N 項」。
- 點右邊的「已選 N 項 · 清除」會清掉**目前頁籤**的勾選（範圍跟旁邊的「全選」一致）。
- 其他頁籤也有勾選時，右側會多出「全部 N · 清除」，那顆才是清除所有頁籤；平常不會出現，不佔位置。
- 計數的位置固定，不會因為「顯示全選列」開關而移動 —— 該設定只控制左邊的全選要不要出現。
- **在有下層的項目上按右鍵 = 展開／折疊**，不用瞄準左邊那個小三角。沒有下層的項目按右鍵則是 Power BI 原本的內容功能表。
- 標題與搜尋列之間有 **全部展開／全部折疊** 兩個按鈕，只作用在目前頁籤；該頁籤沒有階層時會自動隱藏。按過之後會蓋過格式窗格的「預設全部展開」設定。
- **Shift 區間勾選**：按住 Shift 點第一項（設為起點，該列左側出現強調色標記），再按住 Shift 點第二項，中間所有列一起設成同樣狀態，起點隨即清除。
  **一般點擊不會影響起點** —— 隨手勾過的項目不會變成區間起點。切換頁籤或改搜尋字串時起點會清掉。
  範圍以**畫面上看得到的列**計算，折疊起來的子項不會被掃到。單選模式下不作用。
- **搜尋後全選**：輸入搜尋字串後，最上面的全選列會變成「全選搜尋結果（N）」，只對符合的項目作用。

### 篩選模式

| 模式 | 行為 |
|---|---|
| **篩選器 (Filter)** | 送出真正的篩選條件，等同原生交叉篩選器，會出現在篩選窗格、影響所有視覺。單層頁籤用 `BasicFilter (In)`，多層頁籤用 `TupleFilter`（多欄位組合）。各頁籤各出一組條件、彼此 AND |
| **選取 (Select)** | 用 `SelectionManager` 做交叉醒目提示，其他視覺是高亮而非過濾 |

篩選模式下狀態會自動還原：報表重開、切換書籤、篩選窗格清除、同步篩選器帶進來的條件，都會反映回勾選框。

切換模式時會自動清掉另一種模式留下的狀態 —— 從「篩選器」切到「選取」會先移除已送出的篩選條件，否則報表還被舊條件篩著，交叉醒目提示會看起來像沒生效。

### 伺服器端搜尋（突破 30,000 列上限）

預設的搜尋是**純前端**的，只掃已經抓進視覺的資料。一旦資料被 30,000 列上限截斷，超出的項目搜尋不到 —— 因為它們根本不在記憶體裡。

格式窗格 → 搜尋 → **伺服器端搜尋**（預設關閉）打開後，輸入關鍵字會送出一個 `Contains` 條件到模型，**查詢本身只回傳符合的列**，所以底層幾百萬列都搜得到。

- 條件是透過 `general.selfFilter` 送的，**只套用在本視覺**，不會篩到其他視覺。
- 打字有 **400ms 防抖**，停手才送出查詢；等待期間搜尋框會有掃描動畫。
- 只在「篩選器 (Filter)」模式下作用。
- **比對層級**：`Contains` 一次只能指向一個欄位，多層頁籤要指定用哪一層比對。`1` = 最上層，`0`（預設）= 最底層。
- 切換頁籤時已送出的搜尋條件會作廢（條件綁在原頁籤的欄位上）。

什麼時候該開？維度基數超過數萬、或右上角出現資料截斷警告時。基數不大就別開，前端搜尋沒有延遲、而且能同時比對所有層級。

### 說明按鈕

標題列右側的 **?** 點開後會蓋出一張操作說明面板，把右鍵展開、Shift 區間勾選、搜尋全選這些不容易被發現的功能列出來給報表使用者看。點面板以外的地方或右上角 ✕ 即可關閉。

- 格式窗格 → 標題 → **顯示說明按鈕**（預設開啟）
- 格式窗格 → 標題 → **說明文件網址**：填入 `https://` 開頭的網址後，面板底部會多一個連結。自訂視覺跑在沙箱 iframe 裡，所以是透過 `host.launchUrl()` 開啟，不能直接用 `<a>`。

說明內容寫在 `src/visual.ts` 的 `HELP_SECTIONS`，**改功能時記得一起更新**。

### 頁籤色彩

格式窗格 → 頁籤 → **啟用頁籤色彩**（預設關閉）。打開後才會出現各頁籤的背景色選擇器。

- 目前頁籤用**完整的顏色**，其他頁籤自動淡化 45%，維持「哪個是選取中」一眼可辨。
- 文字顏色依背景亮度**自動切換深色或白色**，深色背景不會看不到字。
- **強調色仍然存在** —— 選取頁籤底下的底線、勾選框、已選取圓點都還是走「項目 → 強調色彩」，不受頁籤色彩影響。
- 高對比模式下不套用自訂色，改用作業系統配色。

預設配色**依頁籤總數自動產生**：把色相平均分配一圈，所以不管開幾個頁籤都是不重複的顏色，改數量時配色會自己跟上，不需要維護色票。想調整整體色調，改 `src/settings.ts` 最上方三個常數即可（飽和度、亮度、起始色相）。

## 頁籤之間互相篩選

在頁籤 1 勾了「品牌 = A」，切到頁籤 2 時清單只剩品牌 A 底下的品類 —— 這是把多個原生篩選器整合進一個視覺後應該保有的行為。

格式窗格 → **篩選行為 → 頁籤之間互相篩選**（預設開啟，僅在「篩選器 (Filter)」模式下作用）。

### 原理

Power BI 預設**不會**把一個視覺送出的篩選套回它自己的查詢。所以視覺送出兩份條件：

| 屬性 | 內容 | 對象 |
|---|---|---|
| `general.filter` | **全部**頁籤的條件 | 其他視覺 |
| `general.selfFilter` | **目前頁籤以外**的條件 | 本視覺自己 |

排除目前頁籤是必要的 —— 否則勾了 A 之後清單只剩 A，就再也改選不了 B。因為條件隨「目前是哪個頁籤」而變，**切換頁籤會重新查詢一次**，畫面會閃一下；大模型上可能有零點幾秒延遲。介意的話可以關掉這個開關。

### 勾選狀態怎麼保住

其他頁籤的項目會被 `selfFilter` 濾掉而從資料裡消失。如果每次都從畫面上的樹重算條件，那些條件會憑空不見 → 條件消失 → 資料回來 → 條件又出現，來回震盪。

所以視覺在**勾選當下**（該頁籤正在顯示、清單完整）就把「葉層路徑」存下來，條件一律從這份存量組出來，不受後續資料增減影響。同理，資料被篩到 0 列的頁籤仍會保留，不會被當成失效清除。

## ⚠️ 三個限制，都是 Power BI 本身的規則

### 1. 所有頁籤的欄位必須來自「有關聯」的資料表

放入模型中彼此沒有關聯路徑的表，會得到：

```
InvalidUnconstrainedJoin
Not showing data for DataShape 'DS0' because it's not clear how these fields are related.
```

因為 **Power BI 一個視覺只執行一次查詢**，所有頁籤的欄位全部進同一個 DataShape，查詢引擎拒絕產生無關聯資料表的笛卡兒積。這跟頁籤怎麼分無關 —— 對查詢產生器來說「頁籤」不存在，它只看到「這個視覺綁了 N 個欄位」。原生的「資料表」視覺放入同樣的欄位也會得到一模一樣的錯誤。

**無解，只能在模型裡建立關聯，或不要放那張表的欄位。**

### 2. 各頁籤的欄位會交叉組合，總列數上限 30,000

同樣因為共用一次查詢，回傳列數 = 各頁籤欄位組合數的乘積。視覺內部會依資料角色分群並去重，畫面呈現是正確的，但資料被截斷時清單會缺項（右上角會出現警告圖示）。

- ✅ 適合：低基數維度（品牌、品類、系列、地區、渠道、部門、狀態…）
- ❌ 不適合：高基數欄位（訂單編號、客戶 ID、日期時間、SKU 明細）

  一個 `fortune_order_id` 就會把 30,000 列吃光，其他頁籤全部缺項。

### 3. 各頁籤共用同一次查詢，無法個別控制

上面兩點的共同根源。此外「篩選依據量值」是整個視覺共用的，不能針對某個頁籤單獨設定。

## 調整頁籤欄位區塊的數量

資料區塊（`dataRoles`）必須在 `capabilities.json` **靜態宣告**，SDK 不允許執行期動態新增，**格式化窗格也無法調整** —— 格式窗格只能改外觀與行為，不能生出新的欄位放置區。所以這裡預先開好 20 個，管理者放幾個就出現幾個頁籤。

要增減數量，用附的腳本一次改完（共四處，手改容易漏）：

```bash
node tools/set-tabs.js 12    # 改成 12 個頁籤欄位區塊
npm run package              # 重新打包
```

也可以走 npm script：`npm run set-tabs -- 12`。git bash 裡路徑要用**正斜線**，反斜線會被當成跳脫字元。

腳本會同步更新：

1. `src/dataModel.ts` 的 `MAX_TABS`
2. `capabilities.json` → `dataRoles`（tab1..tabN）
3. `capabilities.json` → `dataViewMappings[0].categorical.categories.select`
4. `capabilities.json` → `objects.tabs.properties`（name1..nameN、bg1..bgN）

跑完會印出專案路徑、收到的參數、改動前的值，並在寫入後重新讀檔逐項驗證，同時把完整訊息寫到 `tools/set-tabs.log`。**沒看到五項全部 `[OK]` 就是沒改成功。**

版面計算、格式窗格、預設頁籤配色都會自動跟著 `MAX_TABS` 走，不需要手動補。

> **只跑這支腳本不會改變 Power BI 裡的視覺** —— 一定要接著 `npm run package`，再到 Power BI Desktop 移除舊視覺、重新匯入。

## 開發

### ⚠️ 專案路徑必須是純英文

`pbiviz package` 在**含中文（或任何非 ASCII 字元）的路徑**下，會讓 node.exe 直接 segfault：

- 沒有 stdout、沒有 stderr、離開碼異常
- Windows 事件檢視器查不到（沒有 Event 1000/1001）
- 只留下寫到一半的 `.tmp/precompile/visualPlugin.ts`（0 bytes）
- git bash 下會顯示 `Segmentation fault`，cmd/PowerShell 下則完全靜默

**`npm install` 在同樣路徑下完全正常**（它只解壓檔案），所以極容易誤判成 npm 壞掉、防毒攔截或專案設定錯誤。

本專案因此從 `...\pbiviz\自定義篩選器` 改名為 `...\pbiviz\self-defined_filter`。中文可以繼續留在 `capabilities.json` 的顯示名稱 —— 那是**檔案內容**不是路徑，完全不受影響。

### 指令

```bash
npm install        # 第一次必跑，約 340 個套件
npm start          # pbiviz start，開發者視覺即時預覽
npm run package    # 產出 dist/*.pbiviz
npm run typecheck
```

打包卡住時先刪掉殘留的 `.tmp/` 再試。

### 實作備忘

踩過的坑，改動前先看一眼：

- **`capabilities.json` 的屬性名必須與 `settings.ts` 的 `name` 完全一致**，否則 Power BI 會**靜默丟棄**該設定，不報任何錯。字型大小曾因為宣告成 `font`、程式讀 `fontSize` 而整個失效。
- **filter target 一律從 `queryName` 拆真實表名／欄位名**，不能用 `displayName`。使用者在視覺上重新命名欄位後 `displayName` 會變，篩選會打不到、還原比對也會失敗。
- **`capabilities.json` 只能有一組 dataViewMapping 條件成立**。早期版本寫成「每個頁籤一組 mapping」，同時放兩個頁籤會讓查詢產生器崩潰（`visitRole / Cannot read properties of null`）。
- **篩選條件一律從 `selection` 存量組出，不從樹重算**。自我篩選會讓其他頁籤的項目從 dataView 消失，從樹重算會造成條件震盪。
- **`transform` 保留 0 列的頁籤**，理由同上。
- 建樹時以 key 去重，所以各頁籤欄位交叉組合產生的重複列會自動收斂。
- 還原勾選時「認得的條件才覆寫」；完全比對不到就保留現況，避免因欄位名稱對不上而清空使用者的選擇。
- 版面計算不要寫死頁籤數上限，一律讀 `MAX_TABS`（`tabsPerPage()` 曾寫死 8，導致調大數量後每頁仍只顯示 8 個）。

## 疑難排解

| 症狀 | 原因 / 解法 |
|---|---|
| `npm run package` 沒輸出就結束／git bash 顯示 `Segmentation fault` | **專案路徑含非 ASCII 字元**。搬到純英文路徑。見開發章節 |
| `Command failed: npm list powerbi-visuals-api` | 沒跑過 `npm install`；或用到全域的舊版 pbiviz。先 `npm install` |
| `InvalidUnconstrainedJoin` | 頁籤裡混了無關聯的資料表。見限制 1 |
| 清單不隨其他視覺的篩選縮減 | 沒放「篩選依據量值」 |
| 切到別的頁籤，清單沒被本視覺的勾選縮減 | 格式窗格 → 篩選行為 → 開啟「頁籤之間互相篩選」；且篩選模式要是「篩選器 (Filter)」 |
| 切換頁籤時畫面閃一下／有延遲 | 「頁籤之間互相篩選」開啟時每次切頁籤都會重新查詢。不需要的話關掉即可 |
| 右上角出現警告圖示 | 資料達 30,000 列上限，把高基數欄位移出去；或開啟「伺服器端搜尋」讓使用者仍能搜到被截斷的項目 |
| 搜尋不到明明存在的項目 | 資料被 30,000 列上限截斷了。格式窗格 → 搜尋 → 開啟「伺服器端搜尋」 |
| 拖了欄位卻沒出現頁籤 | 該欄位所有值都是空的；或 `capabilities.json` 的 `select` 漏了該角色（用 set-tabs 重建） |
| 勾選後其他視覺沒反應 | 篩選模式被設成「選取 (Select)」；或報表設定為不允許互動 |
| 交叉醒目提示沒生效 | 依序檢查：① 篩選模式要設成「選取 (Select)」 ② 報表上「編輯互動」中，本視覺對目標視覺的設定不能是「無」 ③ 目標要是**有量值的圖表**（長條圖等），資料表/矩陣看起來就像被過濾 ④ 舊版有兩個 bug（切模式沒清舊條件、selectionId 建法錯誤），請重新匯入最新的 .pbiviz |
| 雲端版列數超過高度時字變模糊 | 清單出現捲軸會讓瀏覽器把它提升成合成圖層，在縮放過的報表畫布下會模糊。已加上 `translateZ(0)` 改善。若仍模糊，把報表檢視切成「實際大小」確認 —— 那是 Power BI 服務縮放整個畫布造成的，所有視覺都會受影響 |
| 改了格式設定沒反應 | 該屬性可能沒在 `capabilities.json` 宣告，或名稱與 `settings.ts` 不一致 |
| 看不到各頁籤的背景色設定 | 格式窗格 → 頁籤 → 先打開「啟用頁籤色彩」 |
| 重新匯入視覺後沒變化 | 先在視覺效果窗格移除舊的，再匯入 |

## 已知限制

- 選取模式下，多層頁籤的交叉醒目提示以「勾選節點所在層級」的識別為準。
- 「勾選父項時連動子項」關閉時，父層仍會依子層狀態顯示半選，但只有實際勾到的節點會送進篩選。
- 頁籤數量上限 50（`tools/set-tabs.js` 的防呆），實務上受視覺寬度限制，超過 20 個已不易操作。
